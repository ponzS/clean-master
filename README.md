# clean-master

一个原生 macOS 磁盘清理应用。SwiftUI 界面，本地规则扫描，无第三方依赖、账号、网络请求或 AI token 消耗。

## 使用

1. 打开 `dist/clean-master.app`，点击 **扫描可清理项目**。
2. 按占用和影响选择项目；信息按钮能查看实际路径。磁盘清理项目初始不勾选。
3. 选择 **移到废纸篓**（默认，可恢复）或 **永久删除**，检查确认面板后执行。
4. 结果逐项显示成功或失败，失败不计为成功；清理后自动重新扫描。

移到废纸篓不会立即释放空间。应用不会代你清空整个废纸篓。永久删除不能撤销。模拟器设备、系统及共享缓存只支持永久模式，通过 `xcrun simctl` 管理。

## 应用卸载与数据

左侧打开 **应用卸载与数据**，选择已安装应用，选择以下操作：

- **卸载应用与数据**：处理应用本体以及勾选的关联数据。明确关联的数据默认选中；未勾选的数据保留。先处理数据，再移除应用；所选数据处理失败时保留应用，方便重试。
- **仅清理应用数据**：应用本体始终保留，只处理勾选的数据。该限制也在清理核心中执行，不仅依赖界面复选框。

默认采用移到废纸篓，两种操作都需要在具体清单上再次确认。关联数据可能包含设置、登录状态、本地数据库、未同步内容或扩展，清理前请检查影响说明。不会删除云端账号或云端数据。

应用列表扫描 `/Applications` 与 `~/Applications`（最多三层）。按 bundle identifier 识别缓存、偏好设置、应用支持目录、沙盒、WebKit 和 HTTP 存储；提供 VS Code、Chrome、Brave、Cursor、懒猫微服的已知路径映射。仅名称相同的目录单独标记，默认不选。相同标识符的多个安装副本可能共享数据，界面会提示。

系统内置应用和 clean-master 自身不可卸载。共享容器、钥匙串、系统服务、后台助手与自定义数据路径不在自动处理范围内，不能保证每个第三方应用都完全无残留。有数据无法读取时会阻止卸载；可以先解决权限，或仅清理已经确认可读的数据。应用运行时不能处理其数据。系统级安装器或驱动仍需使用厂商提供的卸载器。

## 扫描范围

- CocoaPods、npm/npx、pnpm、React Native、Go、Cargo、Playwright、DotSlash 等缓存。
- Brave、Chrome、懒猫微服的明确缓存子目录，以及 VS Code 启动缓存。
- Xcode 编译缓存、按版本列出的真机调试文件、逐份发布归档。
- iOS 模拟设备、模拟器系统、共享缓存。
- macOS 动态壁纸视频。

默认不扫描桌面、文稿、照片、数据库、钥匙串、聊天记录和工具链。不会扫描整个磁盘后把未知文件自动归类为垃圾。扫描范围在应用中可查看。

## 保护边界

- 只允许清理代码中列出的目录和规定深度的子项目。桌面源码不在范围内。
- 不跟随符号链接、不跨挂载点；包含 `.git` 的目录不允许整体清理。
- 清理前再次检查目标路径、文件系统身份和关联应用是否运行。
- 未完整读取的项目不可清理；权限和 Xcode 工具问题单独显示。
- 默认不申请管理员权限，也不自动关闭应用。不修改桌面源代码或系统组件目录。应用设置与扩展仅在应用管理模块中明确选中后处理。
- 模拟器操作使用固定命令和参数数组，不使用 shell 字符串拼接。
- 占用按已分配块统计并在单个目录内去重硬链接。APFS 克隆、跨项目共享块、快照、并发磁盘写入会导致实际释放量不同。结果中的“空间变化”是操作前后的系统读数，不保证全部由本应用导致。
- 清理记录最多 20 次，保存于 `~/Library/Application Support/clean-master/history.json`。

## 构建

需要 macOS 14+ 和 Xcode / Swift 5.10+。本机开发版本采用 ad-hoc 签名，没有公证，不是 App Store 版本。

```sh
cd ~/Desktop/clean-master
./scripts/build.sh
open dist/clean-master.app
```

在 Xcode 中打开 `Package.swift` 可以查看和编辑源码。构建应用包请使用上述脚本。

```sh
swift test
dist/clean-master.app/Contents/MacOS/clean-master --scan-json
```

`--scan-json` 是只读诊断入口，不提供命令行删除功能。测试仅在项目 `.build/test-fixtures` 中创建和清理自己的文件与模拟应用。

首次扫描如有受保护位置无法读取，可在系统设置 → 隐私与安全性 → 完全磁盘访问权限中手动添加应用，然后重新启动应用再扫描。没有 Xcode 时，普通缓存扫描仍可工作，模拟器部分会报告不可用。
